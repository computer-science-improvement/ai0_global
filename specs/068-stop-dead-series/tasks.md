## Deltas from the spec

- **T1: anchored legacy codes stay `no_material`** (A5). `source_already_posted:` at the start of the text, the embedded `max_steps: … source_already_posted` form and `preflight_source_used` are still `no_material`, so the 060 tests that pin them are unchanged. Only a guard code inside an agent's sentence is `source_used`, and the new-format `skipped by agent: source_used:`. A streak cannot tell the two apart (one family).
- **T1: `planner_*` is read with the `preflight_*` codes,** before the story check, not after it: the planner's own reason may mention a story, and its code must decide.
- **T1: `cause` is optional in the JSON schema** (the model sees it as required in the description, and a `refine` fails a call with neither `cause` nor `code`). A5 says optional with a `code`; a flat `required` would have refused `code`-only calls from the live-slot and story-guard prompts.
- **T1: one prompt line.** Only `prompts.ts` (executor user prompt) and the zod `describe` name the enum, as A5 says; the other «skip_slot з причиною» lines are unchanged.
- **T1: `StreakHit.cause` is `PauseCause`** (`no_material | source_unreachable`). A critic run is no longer a hit at all, so `PAUSING_CAUSES` stays only as the check in the breaker. `SkipCause` gained `source_used` and `quality`.
- **T1: the fixture holds 45 rows,** all slots of the replayed groups (Prompt, pdr, «AI-новини дня», @game_exchange_dev plain and «Знижки тижня», and 89320f09), not only the skips: the post and the critic rows are what end or pass a run.
- **T1: dashboard labels** (optional in the spec): `skipReason` shows the named cause, the planner's empty day and `preflight_no_material`.
- **T2: `cause` has no zod default.** It is optional and read as `other` (A5 wording: «default `other`»), so the inferred plan type keeps old callers and tests compiling; the schema description says so.
- **T2: `planPerDay` counts paused instances itself.** A7 says «subtracts only `dueInstances`», but a paused series is not due (`dueInstances` skips it), so the function reads the paused series' cadence on the plan weekday (`pausedInstances`). It stays pure and only does so when the context carries `paused`, `series` and `clocks`; old callers (rules, pins, date only) get exactly what they got.
- **T2: silent days use the pause-only minimum.** `ScheduleService.minPerDay(card, day, now)` returns the card's `postsPerDayMin` minus the paused instances (a resource pause = 0); it does not apply frequency rules or pins, which are the planner's business and would hide a real dark day. The hook is optional, fails open to the card's own minimum, and is wired in `load()` only (069 edits the rest of `silent-days.ts`).
- **T2: placeholders are channel-wide deduped, and stay where they were.** A replan marks the old plan's future placeholders `superseded by a new plan` (they are not moved to the new plan, as `skipped` slots never are), and `NOT EXISTS` looks at every unsuperseded `planner_*` placeholder of the channel with the same series and time, or, for a short day, the same resource and local day window. A placeholder whose time has passed stays and counts once.
- **T2: a future placeholder is not a close yet.** The breaker's window ends at `now`, so a 19:00 placeholder declared in the morning counts after 19:00 (a short day counts at once, it is stamped at the planning moment). The planner has no way to bank closes for days to come.
- **T2: network short day.** `short_days[]` takes only resources of the network with a playbook section, once each; the anchor's placeholder has no `resource_ref`, the others carry theirs, and the day window is the resource's own local day.
- **T2: the three PG failures seen in the whole `*.pg.test.ts` run** (`data-query` Cyrillic full-text search, two in `ledger-anchor`) came from the shared scratch database, whose locale was `C` (`lower('П')` does not fold). The lead moved it to `en_US.UTF-8`; on a database made from the new template all three pass.
- **T3: one usable material hint is enough.** A slot fails only when every material hint (URL, row, dataset) fails, and the most informative reason is reported (no material, then spent, stale, blocked). A bad `data://` row beside a `library:<table>` hint that still has rows passes; the review-4 Prompt case (rows without text) fails once the PromptHero rows are unpostable (migration 095, T4), because the dataset's `unposted_here` already counts only postable rows.
- **T3: a hint of another kind cannot be judged and lets the slot run.** `feed:`, `api:`, `network_highlights:` and free text are not material; a slot that carries one beside a failing hint is not stopped. A live slot is not judged (it picks its item at run time).
- **T3: a library slot is skipped, not swapped.** The swap needs an idea with URL sources; a row or dataset failure skips the slot with `preflight_no_material` (or `preflight_source_used` for a spent row). Without the data store wired (`material` absent) a row or dataset hint passes.
- **T3: plan-time checks share the production pre-flight.** `editor.module.ts` builds one `SlotPreflight` (`planPreflight`) and passes it to `buildRoleTools` (with `env`, for the format filter) and `buildNetworkTools`. A derived (`duplicate` / `adapt`), reserved or promo slot is not judged; the check never throws (a failure lets the plan through, with a log line). A refusal carries the way out (`PLAN_TIME_WAY_OUT`), a format refusal asks for another format.
- **T3: the data:// check is one place for 071.** The row text lives in `assessRow` (the used reason from `usedWhy`), so 071 adds its «пропущене в цьому колі» text there without touching the plan-time code.
- **T4: the refs query returns rows in the order asked.** The SQL has no order (`ids` and `legacyRefs` are one `OR`); `runQueryData` maps each given ref to its row (by `data://<dataset>/<id>` or by `legacy_ref`) and puts `{ ref, found: false }` where none matches. A row asked through its `library://` alias carries `requested: <that ref>` beside the canonical `ref`. Duplicate refs are dropped before the query.
- **T4: the flags are plain columns.** `postable` and `missing` come from `data_postable` / `data_post_missing` over the schema's rule, `used_here` from `usedRefsCte` (the ledger, waiting posts, the legacy alias) only when a resource is known; `status` is shown only when it is not `active`. A dataset field named like a flag would be overwritten by it.
- **T4: only the zero-hit note was merged with the spec's hint.** The note after an empty result asks the data once more (without `unposted_on`, `limit 1`, with a total) to tell «all used here» from «nothing matches» from «nothing postable». It sits in one function (`zeroHitNote` in `data-tools.ts`) so 071 adds its round text beside it. `search_library` and the dashboard listing are untouched.
- **T4: 095 changes the rule only; the 083 PromptHero loaders are not edited.** With the new rule `data_items_upsert` refuses a PromptHero row without prompt text (the existing 083 insert check, nothing new in code); the runbook says so (§ 27 item 2).
