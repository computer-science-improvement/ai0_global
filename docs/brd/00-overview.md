# BRD (as-is) — ai0_global: огляд продукту

> Статус: чернетка, згенерована з коду 2026-10-05 (гілка `feat/editor-agent`). Описує, як система **фактично** працює зараз. Власник перечитує й виправляє; розбіжності між «як є» і «як має бути» фіксуються в розділах «Спостереження» та «Відкриті питання» кожного документа.

## 1. Що це за продукт

ai0_global — система для власника мережі українських медіаресурсів (Telegram-канали + дзеркала в Instagram / Facebook / Threads, TikTok). Мережа заробляє на рекламі. Система:

- **генерує й публікує контент**: за стратегіями (розклад + джерела даних + AI-генерація) і через автономного AI-редактора, який сам вирішує, що публікувати, на основі історії каналу та статистики;
- **керує мережею агентів**: оркестратор на кожен ресурс, MANAGER над ними, крос-промо між каналами;
- **збирає аналітику** власних і відстежуваних каналів (підписники, перегляди, ER) та шукає нові канали й ніші;
- **продає рекламу**: медіакіт-лендинг, замовлення й оплата через LiqPay, публічні звіти для рекламодавців.

**Продуктове рішення власника (2026-06):** це мережа, якою керує сам власник, а **не SaaS**. Тому немає мультитенантності, один користувач-оператор, один екземпляр сервісу автоматизації. Координація публікацій живе в памʼяті процесу, тож другий екземпляр призведе до подвійних публікацій.

## 2. Користувачі та ролі (as-is)

| Роль | Де | Як потрапляє |
|---|---|---|
| Власник / оператор | `/app/*` (дашборд) | логін за токеном (`/login`) |
| Відвідувач / потенційний рекламодавець | `/` (публічний лендинг) | без логіну |
| Рекламодавець | `/report/$token` | за секретним посиланням на звіт |
| Підписники каналів | Telegram / Meta / TikTok | не взаємодіють із дашбордом; їхні дії (вступи за інвайт-посиланнями, кліки `/r/:code`) збираються для KPI |

Ролей усередині дашборду немає: хто залогінився, той бачить і може все.

## 3. Архітектура (коротко)

| Компонент | Технології | Роль |
|---|---|---|
| `apps/dashboard` | React 19, TanStack Router/Query, Vite, Tailwind v4 (темна тема) | інтерфейс власника, публічний лендинг, звіти |
| `apps/automation` | NestJS 10, raw `pg`, BullMQ/Redis | API `/api/*`, крони, AI-генерація, публікація, збір статистики, агенти |
| `apps/pipeline` | Node-скрипти | офлайн: парсинг/скрейпінг датасетів (рецепти, цитати, ПДР…) → Postgres |
| Postgres 16 | 54 міграції `database/migrations/NNN_*.sql` | усі дані |
| Redis | BullMQ | черги задач |
| nginx (контейнер `dashboard`) | — | віддає SPA, проксить `/api` і `/r/` на automation |
| `backup` | — | резервні копії БД |

**Зовнішні інтеграції:**
- Telegram Bot API (публікація, адмін-бот, `chat_member`);
- MTProto-сесії (статистика, читання каналів, агент-оператор);
- Meta Graph (Instagram, Facebook, Threads);
- TikTok;
- Telegraph (лонгріди);
- LLM: OpenRouter для AI-редактора й агентів, а також Claude / OpenAI / Perplexity / Grok у стратегіях;
- LiqPay (оплата реклами).

Токени зберігаються зашифрованими (AES-256-GCM, ключ `TOKEN_ENCRYPTION_KEY`).

## 5. Ключові наскрізні процеси

1. **Контент за стратегією.**
   - Стратегія задає розклад.
   - Щоразу береться запис із джерела (датасет у БД або зовнішнє API), AI генерує текст.
   - Пост проходить рев'ю, публікується в Telegram і, за налаштуваннями, дублюється в Meta.
   - Використаний запис позначається, щоб не повторюватися (дедуп). → документ 02
2. **Автономний редактор.**
   - На кожен канал своя картка: режим `off` / `shadow` / `live`, бриф, формати, квоти, тихі години.
   - Планувальник будує план слотів на день; агент на кожен слот вирішує, що публікувати, пише PostSpec, проходить lint і guards, публікує.
   - У режимі `shadow` нічого не публікується, лише превʼю.
   - Діє денний бюджет на LLM. → документ 03
3. **Чат з редактором і агентами.**
   - Власник просить пост, агент робить чернетку з Telegram-превʼю.
   - Публікація або планування відбуваються лише за явною командою чи кнопкою.
   - Через `@handle` можна звертатися до конкретного агента. → документ 03/04
4. **Мережа агентів.**
   - MANAGER кілька разів на день читає KPI-дайджест і видає директиви оркестраторам. Структурні директиви йдуть на картку власнику.
   - Є крос-промо через трекінгові інвайт-посилання.
   - Скіли версіонуються, з автовідкатом. → документ 04
5. **Аналітика й розвідка.**
   - Періодично збирається статистика власних і відстежуваних каналів.
   - Будується граф каналів, видаються рекомендації. → документи 05, 06
6. **Реклама.**
   - Замовлення → інвойс LiqPay → вебхук оплати.
   - Далі заплановане розміщення в зарезервованому слоті, публікація, публічний звіт. → документ 08

## 6. Наскрізні бізнес-правила (as-is)

- `BR-GEN-01` Часи для власника — київські (`Europe/Kyiv`). Власні часи ресурсу (слоти, тихі й найкращі години, серії, денна статистика) — у його часовому поясі (за замовчуванням Київ); інтерфейс показує обидва, коли вони різні (spec 024 FR-005).
- `BR-GEN-02` Дашборд `/app/*` доступний лише після логіну; без налаштованої автентифікації сервіс відмовляє в доступі (fail-closed); виняток — `ALLOW_NO_AUTH=true` лише поза `NODE_ENV=production`.
- `BR-GEN-03` Сервіс автоматизації запускається в одному екземплярі; паралельні екземпляри не підтримуються.
- `BR-GEN-04` Токени платформ зберігаються в БД зашифрованими; якщо зашифрованого токена немає, використовується значення зі змінних середовища.
- `BR-GEN-05` AI-агенти не публікують нічого в режимі `shadow`; у режимі `live` публікують лише після lint і guards (пауза каналу, дедуп джерел за 7 днів, бюджет).
- `BR-GEN-06` Агенти на пряме запитання не приховують, що вони AI; тон спілкування професійний і по суті.
- `BR-GEN-07` Структурні зміни, які пропонує MANAGER (нові формати, крос-промо тощо), потребують підтвердження власника через картку дії.

## 7. Глосарій

| Термін | Значення |
|---|---|
| Ресурс | один канал/акаунт на платформі (`telegram:@key`, `instagram:…`) |
| Мережа (network) | група ресурсів (`meta_account_groups`), якою керує оркестратор якірного Telegram-каналу |
| Стратегія | правило «що, звідки, коли й куди публікувати» з AI-генерацією |
| Картка редактора | налаштування AI-редактора для каналу (`editor_channels`) |
| Слот | запланована позиція в денному плані редактора (`editor_slots`) |
| PostSpec | структурований опис посту (формат, тіло, медіа, опитування, кнопки), який рендериться у виклики Telegram |
| Shadow / Live | режим агента: лише превʼю / реальна публікація |
| Скіл | Markdown-інструкція для агента (у файлі або в БД з версіями) |
| Директива | вказівка MANAGER оркестратору (зі статусами й оцінкою ефекту) |
| Плейбук | стратегія ресурсу, згенерована з брифу власника |
