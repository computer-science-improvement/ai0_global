# 01 · Продукт і бізнес

## 1.1 Що це і для кого

**ai0_global** — це **вертикально інтегрований двигун власної медіа-мережі**, а не продукт для продажу іншим. Власник свідомо вирішив **не** будувати SaaS: немає multi-tenant, немає onboarding, немає per-user scoping. Один власник = один інстанс = одна мережа каналів.

**Хто «користувач»:** сам власник (оператор мережі). Дашборд — це його пульт керування, а не кабінет клієнта.

**Яку роботу система виконує за власника:**
1. Сама набирає й веде **портфель нішевих Telegram-каналів** (плюс дзеркала в Meta/TikTok).
2. Сама **виробляє контент** під кожен канал (парсинг джерел + генерація Claude у голосі каналу).
3. Дає інструменти, щоб **монетизувати** цю аудиторію рекламою — з агентом, що триажить запити й доводить угоду до оплати.

## 1.2 Дві бізнес-петлі

### Петля 1 — Створення цінності (аудиторія)

Кожна стратегія на кожен «тік» крону проходить конвеєр:

`fetch (джерело) → dedup (не повторюватись) → AI-generate (Claude, голос каналу) → review (AI-рецензент) → publish (Telegram + дзеркала) → track (метрики)`

Це нарощує аудиторію 16 різних нішевих каналів.

### Петля 2 — Захоплення цінності (гроші)

Агент-оператор із 4 етапів (усе **owner-approved**, нічого автономного):

| Етап | Що робить | Стан |
|---|---|---|
| **SP1 — DM-інбокс** | читає вхідні DM (реклама/ВП), класифікує, готує чернетку відповіді (read-only) | ✅ |
| **SP2 — Дії за апрувом** | ти апрувиш надсилання відповіді або планування спонсорського поста | ✅ |
| **SP3 — Оплата** | LiqPay hosted-checkout + підписаний webhook → інвойс `paid` | ✅ |
| **SP4 — Розвідка чатів** | моніторить уже-додані адмін/ВП-чати, витягує можливості (реклама/ВП/прайс) | ✅ |

**Як реально робиться $:** агент бачить рекламний запит (SP1) або можливість у чаті (SP4) → власник апрувить відповідь із платіжним посиланням (SP2/SP3) → рекламодавець платить на сторінці LiqPay → webhook ставить `paid` → власник одним кліком планує спонсорський пост (SP2) → публікація йде тим самим движком, що й органічний контент.

> ⚠️ **Чесно:** створення цінності (Петля 1) реалізоване значно глибше, ніж захоплення (Петля 2). SP1–SP4 закривають механіку, але це **owner-in-the-loop** інструменти, а не автономна рекламна біржа. Реальний дохід залежить від ручної роботи власника.

Кожна стратегія — це `ContentStrategy` з власним джерелом, голосом (skill) і платформами. Згруповано за типом джерела:

### Свіжий контент з API/RSS (генерується щоразу)
| Стратегія | Джерело | Генерація |
|---|---|---|
| **ai0-news** | RSS/скрейп (AI/tech/energy/sport) | Claude + `AI0_NEWS_CHANNEL_SKILL`, semantic-dedup, topic-route |
| **ua-news** | RSS (feedUrl per-binding) | той самий конвеєр, що ai0-news |
| **daily-photo** | NASA APOD API | Claude-опис укр. + `PostValidator` |
| **on-this-day** | Byabbe API (події дня) | Claude + `ON_THIS_DAY_CHANNEL_SKILL` |
| **movies** | TMDB trending | Claude + `MOVIES_CHANNEL_SKILL` |
| **space** | Space-news API | Claude + `SPACE_CHANNEL_SKILL` |
| **game-channel** | GamerPower / Epic / Steam / game-news | Claude + `GAMING_CHANNEL_SKILL`, ReviewAgent |

### Контент з БД-пулів (pre-loaded датасети)
| Стратегія | Таблиця | Особливість |
|---|---|---|
| **quotes** | `quotes` | без AI — очистка тексту + пряма публікація |
| **facts** | `facts` | faktypro.com.ua; опційний curated-підпул за `articleTitles` |
| **pdr-quiz** | `pdr_questions` | публікує як **нативні Telegram-опитування** (sendPoll) з обрізанням під ліміти 300/100/200 |

### Мультиплатформні (Telegram + Meta)
| Стратегія | Джерело | Нюанс |
|---|---|---|
| **ai0-prompts** | PromptHero-скрейп + `prompts` | у Meta лише категорія **fashion**; у Telegram — повна ротація |

## 1.4 Чому single-tenant — це рішення, а не недоробка

- Уся координація публікацій — **у памʼяті процесу** (див. [03-data-and-queues](03-data-and-queues.md)), тож **два інстанси = задвоєні пости**. Це навмисна межа.
- Немає `user_id`-скоупінгу, ролей, кабінетів. Гарди — прості shared-secret перевірки (доречно для одного власника).
- Плюс: різко простіша модель (один процес, один Postgres, один Redis). Мінус: щоб продати іншим — потрібна велика перебудова (6–12 міс), тому цей шлях свідомо **не** обрано.

## 1.5 Головна бізнес-вразливість (чесно)

**Моат** (те, чого нема у Buffer/Postiz) — це **шар інтелекту**: трекінг конкурентів через MTProto, граф рекламних звʼязків (`tracked_ad_edges`), ROI-аналіз (`tracked_roi_cache`) і агент-оператор. Але:
- цей моат **тримається на MTProto-акаунтах**, тобто на ризику бану Telegram (див. [05](05-strengths-weaknesses-risks.md));
- монетизація **ручна** (owner-approved), не автономна;
- одна людина = і оператор, і «продавець реклами». Масштаб упирається в час власника, не в код.
