# 05 · Сильні / слабкі сторони та ризики (чесно)

Цей розділ — для команди, без спіну. Оцінка з попереднього аудиту: **концепція 7/10, виконання 6/10.** Нижче — конкретика по коду.

## 5.1 ✅ Сильні сторони

| # | Сильна сторона | Чому це реально сильно |
|---|---|---|
| S1 | **3-шаровий дедуп** | глобальний URL (`posted_news`) + per-destination JSONB (`postedKey`) + AI-новизна (`SemanticDedupService`). Найскладніша частина мультиканальної публікації — зроблена правильно, без join-таблиць |
| S2 | **`RunTracer` обсервабіліті** | ambient `AsyncLocalStorage`: будь-який сервіс углибині пише `span()` без прокидання аргументів → `strategy_runs.steps` → видно в дашборді де саме зламалось |
| S3 | **Шифрування + fail-closed auth** | AES-256-GCM `enc:v1` конверт; JWT_SECRET обовʼязковий у prod; auth **не** відкривається за відсутності токена |
| S4 | **597 бекенд-тестів, 0 фейлів** | 117 файлів; покривають стратегії, publisher-и, дедуп, трекінг, chat-intel, крипту |
| S5 | **Моат = інтелект-шар** | трекінг конкурентів (MTProto), граф реклами (`tracked_ad_edges`), ROI (`tracked_roi_cache`), агент-оператор — чого немає у Buffer/Postiz |
| S6 | **Чиста дизайн-система дашборду** | єдиний набір компонентів (Modal, SegmentedTabs, Badge, card-rows), CSS-змінні, один акцент |
| S7 | **Config-in-DB + hot-reload** | правки конфігу з дашборду застосовуються без рестарту (Redis `config:changed`) |

## 5.2 ⚠️ Слабкі сторони та ризики

### 🔴 Критичні / структурні

- **W1 — Стеля «один інстанс».** Уся координація (in-flight, throttle, cooldown) — у памʼяті; `failOrphanedRunning()` вбиває всі `running` на boot; немає розподіленого локу; JSONB-дедуп без DB-unique. **2 інстанси = задвоєні пости.** Горизонтальне масштабування = переписати координацію. *(деталі: [03 §3.3](03-data-and-queues.md#стеля-один-інстанс))*
- **R1 — Ризик бану Telegram (MTProto read+write на юзер-акаунтах).** Трекінг + агент-DM + chat-intel працюють через реальні акаунти. Пом'якшено: ролі розділені (`role='agent'`), off-by-default, `TELEGRAM_TRACKING_SHARE_SESSION=false`. Але це **екзистенційний** клас ризику для авто-паблішера.
- **R2 — SPOF: Supabase + Anthropic.** Хостинг слайдів каруселі = Supabase; вся генерація/дедуп/класифікація = Anthropic. Впаде будь-що з двох — відповідні стратегії/агент стають.

### 🟠 Важливі

- **W2 — Дашборд: ~0 тестів.** 117 тест-файлів на бекенді проти **нуля** на фронті — а саме дашборд запускає деструктивні мутації (delete, approve, оплата).
- **R3 — AI-вартість без жорсткого стелі.** Пре-фільтри й курсори обмежують, але не капають; prompt-кешування **відкладено** (пінната `@anthropic-ai/sdk` не має `cache_control`) → системний промпт біллиться щоразу.
- **R4 — Копірайт на новинах.** ua-news/ai0-news переписують RSS-джерела AI-ом. Атрибуція джерела в моделі є (і ми нещодавно зберегли її на Meta-крос-пості), але derivative-works ризик на Meta лишається.
- **W3 — Агентний FLOOD_WAIT без backoff.** `agent-mtproto.client.ts` на флуд-вейт **лише логує** і повертає `[]` (3 місця) — жодної затримки. Сталий флуд-вейт довший за інтервал крону = повторні невдалі спроби щотіку. (Трекінг-підсистема через BullMQ backoff — сильніша.)

### 🟡 Дрібніші / гігієна (варто на слайд «tech debt»)

- **W4 — Swagger `/api/docs` без гарда і не dev-gated.** `main.ts` викликає `SwaggerModule.setup('api/docs')` безумовно → повна поверхня API + X-API-Key-схема публічно видимі в prod. *Перевірити/закрити.*
- **W5 — CORS захардкоджено** `['http://localhost:5173']` у `main.ts`, `credentials:true`, без env-override. Прод працює лише тому, що дашборд same-origin за Caddy; латентний ризик при будь-якій крос-орідж-топології.
- **W6 — TLS/публічна доступність залежить від ЧУЖОГО Caddy** (стек n8n), який цей репозиторій не контролює й не версіонує. Впаде той стек — дашборд офлайн, і в нашому коді нема чим це задетектити.
- **W7 — `TOKEN_ENCRYPTION_KEY` опційний** → є graceful-шляхи до plaintext-зберігання токенів; оператор, що не виставив ключ, тихо їде з незашифрованими секретами в Postgres.
- **W8 — `ai_logs` росте безмежно**, поки `RETENTION_ENABLED` не увімкнено (за замовч. off) — реальний ризик диску на довгому одноінстансному деплої.
- **W9 — `jokes`** — мертва таблиця; **`STRATEGY_RUN_TIMEOUT_MS` (5 хв) і Alerting `stuckRunning` (20 хв)** — два незалежні, різно-налаштовані запобіжники того самого (не звʼязані — це ок як defense-in-depth, але варто знати).
- **W10 — Single-tenant за дизайном** — немає multi-user; щоб продати іншим = велика перебудова.

## 5.3 🛠️ Що щойно закрили (цей цикл)

Ці пункти вже **виправлені** (у гілці, не змержено) — варто показати як «зробили за останній спринт»:

- **auth fail-closed** + `ALLOW_NO_AUTH` gate (забутий токен більше не відкриває API);
- **TikTok-токени зашифровані at-rest** (були єдині plaintext);
- **атрибуція джерела** зберігається при крос-пості в Meta;
- **per-run timeout** (`STRATEGY_RUN_TIMEOUT_MS`) — фікс «застряглих running»;
- **migration advisory lock** — безпечний конкурентний boot;
- **ретенція** (nightly prune, safe-by-default);
- **проактивний алертинг** власнику при серії помилок/застряглому прогоні;
- **агент-оператор SP1–SP4** повністю (монетизаційна петля).

## 5.4 🧭 Дорожня карта (пріоритети команди)

**Швидкі перемоги (high impact / low effort):**
1. Закрити Swagger `/api/docs` за гардом + dev-gate; винести CORS в env.
2. Увімкнути ретенцію `ai_logs` (або prod-дефолт on).
3. Boot-warning, якщо `TOKEN_ENCRYPTION_KEY` не виставлений у prod.
4. Додати backoff у агентний FLOOD_WAIT (як у трекінгу).

**Середні:**
5. Smoke-тести дашборду (Vitest+RTL) — принаймні для мутаційних flow (delete/approve/оплата).
6. Prompt-кешування Anthropic (після апгрейду SDK) — пряма економія на кожному пості.
7. Прибрати мертвий код (`jokes`), «чесна» абстракція стратегій + TikTok під `BasePublisher`.

**Стратегічні (рівень рішення):**
8. **Явно вирішити питання масштабу:** або переписати координацію на Redis-локи (горизонтальне масштабування), або **формально задокументувати «1 інстанс»** у docker-compose, щоб ніхто випадково не підняв репліку.
9. Зменшити SPOF: локальний фолбек для хостингу слайдів; fallback-модель/черга для AI.
10. Runbook «ризик бану платформ + відновлення акаунтів» + централізація всіх rate/poll/cooldown-констант в один конфіг.

## 5.5 Підсумок для слайда

> **Сильний інженерний кістяк** (дедуп, обсервабіліті, крипта, 597 тестів, реальний інтелект-шар як моат), **свідомо простий** single-instance деплой, і **чесно недороблена** периферія: горизонтальний масштаб, ризик бану MTProto, 0 тестів на фронті, кілька гігієнічних дір (Swagger/CORS/секрети/ретенція). Монетизація механічно є (SP1–SP4), але **дохід тримається на часі власника, не на автономності коду.**
