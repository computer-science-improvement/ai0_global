# Pipeline raw data (`apps/pipeline/src/raw-data/`)

Status: the data is still tracked in git, but it no longer ships in the pipeline image. This was
spec 007, T002. Moving it out of git needs object storage, which is the owner's decision, so this
runbook only describes the problem and proposes a migration.

## What is there (measured 2026-10-01)

`apps/pipeline/src/raw-data/raw-data/`: 614 tracked files, **~161 MB**. That is 75 % of all tracked
bytes in `HEAD` once `.pnpm-store/` is untracked.

| Dir | Files | Size | Recipes | Unique names | Used by |
|-----|-------|------|---------|--------------|---------|
| `recipes/` | 27 (`recipes_001..026.json` + `index.json`) | 129.3 MB | 25,001 | 21,788 | `parsers/recipes-epicure.js` → `data/normalized/recipes/recipes.json` |
| `recipes-splits/` | 548 (`recipes_NNN.src_chunk_XX.json` + `.meta.json`) | 13.1 MB | 2,626 | 2,489 | nothing (abandoned split for the pre-translation experiment) |
| `recipes-stub-125/` | 22 (`recipes_005..026.json`) | 13.7 MB | 2,626 | 2,489 | nothing (the same 125-per-chunk sample as `recipes-splits/`) |
| `recipes-ua/` | 15 (+ `translation_state.json`) | 4.5 MB | 696 | 658 | nothing (abandoned: translation now happens at post time) |
| `prompts-github/` | 2 (`nanobanana.md`, `seedance.md`) | 0.15 MB | — | — | `parsers/prompts-github.js` (written by `scrape:prompts-github`) |

Source of the recipes: the `epicure.kaikaku.ai` gallery API (`recipes-splits/*.meta.json`,
generated 2026-05-28).

**Duplication:** the 2,626-recipe sample exists twice (`recipes-splits/` and `recipes-stub-125/`), and
both are subsets of `recipes/`. `recipes-ua/` is a partial translation of the same data. Only
`recipes/` and `prompts-github/` are read by any code. The other ~31 MB is dead weight.

The parser output `data/normalized/recipes/recipes.json` is gitignored and regenerated by
`pnpm --filter pipeline run parse:recipes` (or `parse`, which now includes it).

## What changed in spec 007

- The root `.dockerignore` excludes `apps/pipeline/src/raw-data`, so the pipeline image no longer
  carries ~161 MB.
- The `pipeline` compose service mounts `./apps/pipeline/src/raw-data` read-only at the same path,
  so `pnpm pipeline:parse` and `pnpm pipeline:sync` still find the files.
- If the directory is missing (for example in a slim checkout), `recipes-epicure` skips with a
  warning instead of killing `run-parsers`.

## Proposed migration (owner decision)

1. **Delete the dead copies** (`recipes-splits/`, `recipes-stub-125/`, `recipes-ua/`, ~31 MB). No
   code reads them. This step is safe even without object storage.
2. **Pick a canonical home for `recipes/` (129 MB):**
   - *GitHub release asset* (simplest, free): `tar czf raw-recipes-2026-05-28.tgz recipes/` and attach
     it to a `data-raw-recipes-2026-05-28` release. It compresses well because it is JSON.
   - or an *S3-compatible bucket* (Backblaze B2 or Cloudflare R2), if one already exists for backups.
3. **Add a fetch script** `apps/pipeline/src/tools/fetch-raw-data.sh` that downloads the archive,
   checks its `sha256` (pinned in the script) and unpacks it to
   `apps/pipeline/src/raw-data/raw-data/recipes/`. Add `pnpm --filter pipeline run fetch:raw`.
4. **Untrack it** with `git rm -r --cached apps/pipeline/src/raw-data/raw-data/recipes` and gitignore
   it. `prompts-github/` (150 KB) can stay tracked.
5. *(Optional)* Purge it from history: [repo-history-purge.md](repo-history-purge.md).

Note: spec 009 retires verbatim Epicure republishing (licensing, see spec 007 T008). After that, the
raw recipe dump may not be needed at all. Decide on step 2 only after 009.
