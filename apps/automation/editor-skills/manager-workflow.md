# Робочий процес менеджера

## Головне правило
**«Продовжуйте як раніше» — правильна відповідь для більшості прогонів.** Директива — лише коли є конкретна підстава в цифрах: аномалія (anomaly), стійкий тренд кілька прогонів поспіль, або очевидна можливість (хіт одного ресурсу, що пасує іншому).

## Порядок
1. Дайджест у промпті (за потреби `get_kpi_digest` ще раз). Спершу аномалії, потім тренди d (%), потім z (наскільки це поза шумом: |z| < 1 — шум).
2. Перевір, чи немає вже відкритої директиви цьому агенту (`list_directives`) і чим закінчились минулі (outcomes у дайджесті, памʼять).
3. Для пояснення конкретного дня каналу — `explain_decision` (channel), `get_network_posts`, `get_platform_stats`, `sql_readonly`.
4. Рішення:
   - нічого не треба → `submit_review` verdict **continue** з 1–3 реченнями підсумку;
   - треба → `file_directive` (до 3) і `submit_review` verdict **directives**.

## Директиви
- `format_shift` — зсунути ваги форматів (params: format, weight_delta ±0.1–0.3).
- `frequency` — частота (params: resource_ref, change_pct; ±30% і більше — структурна, піде власнику).
- `experiment` — спробувати новий формат/кут на кількох слотах (params: what, slots).
- `pause_series` — призупинити серію, що стабільно провалюється.
- `repost` / `cross_promo` — переслати хіт або взаємопіар між ресурсами мережі (структурне для cross_promo; спека 022).
- `advice` / `task` — порада чи разове завдання без метрики.
- Кожна директива (крім advice/task) має **expected**: метрика, напрям, мінімальна зміна у %, і review_in_days (3–14). Evidence — цифри з дайджесту.

## Чого не робити
- Не дублюй відкриту директиву і не повторюй відхилену раніше ніж за 48 год.
- Не давай директив на метриках зі `stale`.
- Не суперечь правилам власника — оркестратор усе одно відхилить.
- Не мікроменеджь: «перепиши пост» — не твій рівень.
