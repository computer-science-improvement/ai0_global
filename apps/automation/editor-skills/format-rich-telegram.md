# Rich-повідомлення Telegram

Telegram (Bot API 10.1) показує пост як структурований документ, якщо в `body` є хоч один rich-блок.
Код сам вирішує, як надіслати: rich-повідомлення, а якщо канал його не приймає — HTML-резерв
(підзаголовки жирним, таблиця моноширинною сіткою або рядками «• ключ — значення», формула як `код`).
Тобто пост завжди дійде; твоє завдання — щоб структура допомагала читачу.

## Блоки
- `heading` `{level: 1–3, text}` — підзаголовок розділу. `level` 2 — звичайний вибір, 1 — лише для дуже довгих постів.
- `olist` `{items}` — нумерований список: кроки інструкції, рейтинг, послідовність. Для переліку без порядку — звичайний `list`.
- `table` `{header, rows}` — до 6 колонок × 20 рядків, клітинка до 200 символів (inline-розмітка можна).
  Кількість клітинок у рядку = кількість колонок у `header`. Перша колонка — назва (модель, місто, тариф).
- `math` `{expression}` — формула в LaTeX (`E = mc^2`, `\frac{a}{b}`), до 500 символів.
- `divider` — тонка лінія між великими частинами. Не частіше одного-двох на пост.
- `details` `{title, body}` — згорнутий розділ: методика, джерела, спойлер-розбір, довгий список. Всередині — звичайні блоки (без вкладених `details`).
- `footer` `{text}` — дрібний текст у кінці: дата цін, «не реклама», умови.
- `code` `{text, language?}` — моноширинний блок: команда, фрагмент коду, конфіг.

## Коли допомагає
- **Порівняння** 3+ варіантів за 2+ ознаками (смартфони, тарифи, ціни в містах) → `table`.
- **Покрокова інструкція**, рецепт, чекліст із порядком → `olist`.
- **Характеристики** (spec sheet) → `table` з двома колонками «параметр — значення».
- **Довгий розбір** (≥ 1200 символів) з 2–4 частинами → `heading` перед кожною частиною.
- **Наука, фінанси, освіта** — формула, яку читач має побачити → `math`.
- **Додаткове, що читатимуть не всі** (методика, повний список джерел) → `details`.

## Коли шкодить
- **Коротка новина** (< 400 символів) — без таблиць і підзаголовків: lead + 1–2 абзаци. Lint попередить (`table_in_short_post`).
- Більше 2 підзаголовків у короткому пості — це вже не пост, а зміст (`too_many_headings`).
- Таблиця з однією колонкою або одним рядком — пиши текстом.
- Альбом і карусель: підпис не буває rich — заголовки й таблиці стануть простим текстом (`rich_in_caption`).
- Не роби з кожного поста документ: структура — для складного змісту, а не для прикраси.

## format_prefs.rich
- `auto` (типово) — rich лише коли в пості є rich-блоки.
- `prefer` — кожен текстовий пост іде rich-повідомленням (навіть без таблиць).
- `never` — завжди звичайний HTML; rich-блоки перетворюються на текст (lint: `rich_off`). Якщо власник закріпив поле — не змінюй.
- Міняй `rich` через `update_resource_format` лише з причиною зі статистики (наприклад, пости з таблицями мають більше пересилань).

## Перевірка
`preview_post` показує `sendRichMessage` серед повідомлень; `lint_post` перевіряє ліміти (32 768 символів, 500 блоків)
і довжину HTML-резерву (≤ 4096): якщо резерв задовгий — скороти таблицю або винеси деталі в `details`/лонгрід.
