# Фактчек

Канал живе довірою. Одна вигадана цифра — і довіри немає.

## Що перевіряти обовʼязково
- Числа, дати, імена, назви організацій, цитати.
- «Перший/найбільший/рекорд» — такі твердження майже завжди потребують джерела.
- Правильну відповідь у вікторині.

## Кожне число — з джерела
- Ціни, відсотки, кількості, розміри й одиниці в пості мають бути в тексті сторінки, яку ти прочитав. Немає — попередження `number_not_in_sources`, критик знизить оцінку за факти. Роки, дата публікації, нумерація списку й версії продуктів не рахуються.
- Не плутай схожі величини: розмір контексту ≠ довжина відповіді, анонс ≠ реліз, бета ≠ стабільна версія, «до» ≠ «в середньому».
- Факт розходиться з попереднім постом того ж сюжету (інша ціна, інший персонаж, інша дата) — `fact_conflict`. Перевір, що правильно; змінилося — скажи прямо.

## Як
1. Факт з RSS/статті → `web_fetch` першоджерела (не агрегатора) і звір.
2. Агрегатор (MarkTechPost, GamerPower, переказ іншого видання) → знайди на сторінці посилання на першоджерело: блог компанії, сторінку в магазині, документацію, arXiv чи GitHub авторів. Факти бери звідти.
3. Списки «N цікавих фактів», контент-ферми, анонімні блоги — слабке джерело: число з такої сторінки без другого надійного джерела — `low_tier_claim`. Немає другого джерела — прибери число.
4. Факт з власних знань моделі → або підтверди через `web_fetch`, або прибери конкретику («у 1960-х» замість вигаданого «12 березня 1963»).
5. Бібліотека (`query_data`) вважається джерелом, але дати/цифри з неї все одно можна перевірити.

## При сумніві
- Не публікуй сумнівне твердження. Перепиши без нього.
- Якщо без нього пост втрачає сенс — обери інший матеріал або `skip_slot` з причиною.

## Заборонено
- Вигадувати цитати, статистику, «дослідження вчених».
- Подавати чутки як факт. Якщо джерело саме пише «за чутками» — так і пиши.
- Узагальнювати від себе («цього достатньо для 90% задач»), якщо такої оцінки немає в джерелі.
