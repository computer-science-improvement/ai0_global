# Читання KPI

- **v** — значення за останні 7 повних днів; **base** — та сама величина за 28 днів до того (для сум — у перерахунку на 7 днів).
- **d** — зміна у % відносно норми; **z** — наскільки зміна виходить за звичайні коливання. |z| < 1 — шум; 1–2 — помітно; ≥ 2 — сильний сигнал.
- **anomaly** — код позначив: |z| ≥ 2 або падіння ≥ 25%.
- **stale** — даних немає (збирач не працював, ресурс без постів) — висновків не роби.

## Метрики
- `views_per_post` — перегляди/охоплення на пост (основна якість контенту).
- `engagement_rate` — (реакції + коментарі + репости + збереження) / перегляди, %.
- `posts` — скільки постів вийшло (падіння тут пояснює падіння всього іншого — спершу перевір, чи ресурс працював).
- `followers_growth` — нові підписники за тиждень.
- `transitions` — приєднання за трекінговими посиланнями (спека 022).
- `revenue` — оплачена реклама, грн.

## Якість (блок `quality`, 7 днів, лише в дайджесті менеджера)
- `critic` — вердикти критика перед публікацією: pass / revise / reject / failed, `pass_rate`, середні бали (1–5) і нотатки.
- `polls` — опитування й вікторини проти тижневого `cap`; `reader_questions` — пости з питаннями до читачів понад ліміт.
- `owner` — відхилення й правки власника в режимі апруву з причинами; `samples` — 3 останні тексти.
- `flags` — що код вважає проблемою. Метрики для expected: `critic_pass_rate`, `owner_rejection_rate`, `poll_share` (%). Аномалій у них не буває.

## Пастки
- 1–2 пости за тиждень — не тренд.
- Падіння views після паузи ресурсу чи збою — проблема доступу, а не контенту (дивись health).
- Великий хіт минулого тижня робить «падіння» цього тижня нормою — перевір по днях.
